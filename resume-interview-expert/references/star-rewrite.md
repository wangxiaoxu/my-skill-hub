# STAR 改写：把职责句变成成果句

面试官不关心「你负责什么」，只关心「你做了什么、怎么做的、结果如何、可不可信」。改写就是把职责句还原成可追问的证据句。

## 1. 成果句公式

```text
动作（强动词）+ 对象（系统/业务/指标）+ 方法（关键技术/策略）+ 结果（数字或可验证范围）
```

例：

- 改写前：`负责交易系统的开发和维护。`
- 改写后：`主导交易系统重构，用 Java + Spring Boot 拆分 12 个微服务，峰值 QPS 从 8k 提升到 25k。`

结果拿不到数字时，用可验证的范围替代：

- `将下单接口 P99 从 <待补：原值> 降到 120ms`
- `支撑日均 <待补：订单量> 单的大促场景`
- `覆盖 3 个业务线、约 20 名研发的协作`

`<待补：X>` 是允许的，编造数字不允许。

## 2. 量化优先

按可信度排序：

1. **绝对值 + 基线 + 结果**：`P99 从 480ms 降到 120ms`
2. **比例**：`故障恢复时间缩短 60%`
3. **规模**：`日均 200 万任务`、`12 个微服务`
4. **范围**：`覆盖 3 个业务线`
5. **周期**：`3 个月内完成迁移`

只有「提升了性能」「优化了流程」不算量化，必须补一个可验证的锚点。

## 3. 动词分级

| 级别 | 动词 | 适用场景 |
|---|---|---|
| A 主导类 | 主导、牵头、设计、搭建、重构、从 0 到 1 | 你是决策者或主要执行者 |
| B 推动类 | 推动、落地、交付、迁移、治理、优化 | 你负责推进与结果 |
| C 参与类 | 参与、协同、支撑、配合 | 你只负责一部分，必须写清边界 |
| D 弱动词 | 负责、完成、进行、跟进、整理、协助、帮助 | 单独使用会显得没有结果，必须配结果 |

用 C/D 类动词不是错，错在**只写动词不写结果**。如果确实只是参与，写清「参与了哪一部分、交付了什么」。

## 4. 弱动词替换表

| 原句 | 替换方向 | 示例 |
|---|---|---|
| 负责接口开发 | 主导 / 交付 | 主导订单接口重构，交付 6 个核心接口 |
| 参与活动策划 | 设计 / 推动 | 设计裂变活动方案，推动 3 个渠道落地 |
| 协助团队维护系统 | 支撑 / 治理 | 支撑交易系统稳定性治理，故障率下降 40% |
| 完成数据整理 | 搭建 / 沉淀 | 搭建指标看板，沉淀 20 个核心指标 |
| 进行性能优化 | 优化 / 重构 | 优化查询链路，接口 P99 下降 65% |
| 跟进线上问题 | 闭环 / 复盘 | 闭环 15 个线上问题，推动 3 项监控补齐 |
| 帮助新人 | 带教 / 赋能 | 带教 2 名新人，独立负责模块开发 |

## 5. 反面例子

| 写法 | 问题 | 改法 |
|---|---|---|
| 负责公司核心业务系统的开发与维护 | 无对象、无结果、无方法 | 主导交易系统重构，拆分 12 个微服务，QPS 提升 3 倍 |
| 使用 React 开发页面 | 工具不是成果 | 用 React 重构商品详情页，首屏时间从 3.2s 降到 1.4s |
| 参与双十一大促 | 边界不清、无贡献 | 负责大促库存服务压测与扩容，支撑峰值 25k QPS |
| 提升了用户体验 | 不可验证 | 优化结算流程，支付转化率从 62% 提升到 71% |
| 熟悉 Kubernetes | 技能不是经历 | 用 Kubernetes 完成 20 个服务容器化，发布耗时缩短 50% |
| 有良好的沟通能力 | 形容词无证据 | 推动产品、研发、运营三方对齐，需求返工率下降 30% |

## 6. 一条 bullet 只讲一件事

- 一条 bullet 里塞 4 个动作，读者记不住，面试官也无法追问。
- 推荐结构：`1 个主动作 + 1 个方法 + 1 个结果`；复杂项目拆成 2–3 条。
- 每条控制在 1–2 行；超过 3 行拆开。

## 7. 改写流程

1. **还原事实**：向用户确认项目背景、你的角色、团队规模、时间、结果。
2. **标记缺口**：哪些数字用户没有？写 `<待补：X>`，不要猜。
3. **选动词**：按实际角色选 A/B/C 级，不夸大。
4. **加结果**：优先绝对值与基线，其次比例与规模。
5. **压力测试**：对每条 bullet 问「怎么做」「为什么这么做」「结果怎么验证」「如果重来怎么改」，答不上来就继续补事实或降级表述。
