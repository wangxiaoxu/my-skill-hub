# ATS 与筛选规则：让机器和人都不误读

ATS（Applicant Tracking System）没有统一标准，但常见实现都依赖**可解析的文本结构**与**关键词匹配**。目标不是「骗过机器」，而是让机器能正确读出你真实的信息。

## 1. 格式禁忌

| 做法 | 风险 | 建议 |
|---|---|---|
| 双栏 / 三栏排版 | 解析顺序错乱，经历与时间错位 | 单栏、从上到下 |
| 表格、文本框、形状 | 内容可能整段丢失 | 用普通段落与项目符号 |
| 页眉页脚放联系方式 | 部分解析器直接忽略 | 联系方式放正文顶部 |
| 图片、图标、二维码 | 无法解析 | 改为文字 |
| 非标准字体 | 渲染错位 | 用常见字体（思源黑体、Arial、Calibri） |
| 特殊符号代替项目符号 | 解析成乱码 | 用 `-` 或 `•` |
| 文件名含空格与中文 | 上传失败或乱码 | `姓名-岗位-年限.pdf` |

## 2. 文件格式

- 优先 **PDF**（版式稳定），但确认目标系统接受 PDF；部分老系统只收 DOCX。
- 不要提交扫描件、图片型 PDF。
- 文件大小控制在 2MB 以内。
- 提交前用文本选择工具检查：能否选中并复制全部文字。

## 3. 关键词策略

1. **用 JD 的原词**，不要只写同义词。JD 写 `Kubernetes`，简历同时出现 `Kubernetes` 与 `K8s`。
2. **关键词要出现在经历里**，不能只堆在技能列表。ATS 与人工都会看上下文。
3. **密度自然**：同一关键词出现 2–4 次足够；机械重复会被人读到。
4. **中英文都写**：`用户增长（User Growth）`，兼容中英文检索。
5. **不要关键词 stuffing**：把无关技术词塞进技能栏，面试第一轮就会暴露。

## 4. 章节与时间线

标准章节名（中英文都常见）：

```text
个人信息 / Contact
求职意向 / Summary
工作经历 / Experience
项目经历 / Projects
教育背景 / Education
技能 / Skills
```

时间线规则：

- 统一格式：`2021.03 - 2025.09` 或 `2021-03 - 2025-09`，全篇只用一种。
- 倒序排列：最近的在最前。
- 每段经历写清 `公司 / 职位 / 地点 / 时间`。
- 不要在时间上造假；背调与社保记录能对上。

## 5. 时间线断裂处理

| 情况 | 简历写法 | 面试说法 |
|---|---|---|
| 主动空窗（学习/休息/家庭） | 写 `2024.06 - 2024.12 职业发展期`，下面列学习或项目 | 简短说明原因 + 这段时间的产出 |
| 被裁 | 正常写离职时间，不标注原因 | 公司业务调整，说明补偿与交接 |
| 转行 | 把可迁移能力前置，项目经历按目标岗位重排 | 讲清动机与已做的准备 |
| 频繁跳槽 | 合并短期经历或只写关键几段，不隐瞒总年限 | 每段给一个客观原因，避免抱怨前公司 |
| 创业 | 写清角色、产品、结果（用户/收入/失败原因） | 讲决策与复盘，不夸大 |

**不要**为了填满时间线编造经历；背调、社保、前同事都可能戳穿。

## 6. 投递前检查表

- [ ] 单栏、无表格、无文本框、无图片
- [ ] 联系方式在正文顶部，邮箱与手机号可复制
- [ ] 章节名是常见写法
- [ ] 时间格式全篇一致、倒序
- [ ] 目标岗位关键词在经历中出现，而不只在技能栏
- [ ] 每条 bullet 有动作与结果
- [ ] 没有 `<待补：X>` 遗漏
- [ ] 文件名规范、PDF 可复制文字
- [ ] 针对该 JD 调整了摘要与前三条 bullet
